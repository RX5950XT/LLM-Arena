# 開發教訓

## 2026-09-01

- 使用者可見的功能入口不能只在有資料時渲染；空狀態要保留說明與下一個可點擊入口。
- 需求中的數量限制要以實際操作需求為準：供應商比較可只選 1 家，競技場模型數量用 2–15 拉桿；裁判不需要提示詞庫入口。
- 取消串流不只要中止 fetch，也要停止後續裁判／歷史儲存，並防止舊回應在使用者重新發送後寫入新結果。
- 已刪除或不再使用的文件不要重新引用；專案說明以 README、CLAUDE.md、CONTEXT.md 和 tasks 文件維護即可。

## 2026-09-02

- 辯論順序設定必須同時接到 UI、恢復暫存、歷史紀錄和 orchestrator；只改畫面會讓實際第一個 API 請求仍固定為正方。
- PDF 匯出要做實際渲染檢查；Canvas 與 PDF 座標系方向不同，單看下載成功或檔案存在不足以確認文字方向。
- 驗證要維持最小必要範圍：功能完成後保留一次 build、一次端到端 smoke 與一次輸出檢查，避免重複跑同一條流程。
- 使用者指出驗證過度時，後續只保留能證明本次背景執行的單次 build 與單次切換 smoke，不重跑已完成的 PDF／舊功能檢查。
